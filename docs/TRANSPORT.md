# 2026-11-14 00:43 MSK — Транспорт GramGrid и BitChat

2026-11-14 00:43 MSK — Решение: вычислительное ядро GramGrid остаётся независимым от мессенджера. Первый крупный обмен между NPU-узлами проверяем в локальной Wi-Fi-сети без доступа в интернет; Telegram — возможный пульт через интернет, BitChat — исследуемый канал обнаружения и короткого управления. Готового адаптера BitChat в GramGrid нет.

## 2026-11-14 00:43 MSK — Проверено по исходным источникам

2026-11-14 00:43 MSK — Последний выпуск permissionlesstech/bitchat — v1.8.0 от 2026-10-23. README описывает две системы доставки: локальная BLE-сеть и интернет-релеи Nostr. Поэтому формулировка «BitChat вообще не использует интернет» верна только для его локального BLE-режима, не для приложения целиком. Источники: https://github.com/permissionlesstech/bitchat и https://github.com/permissionlesstech/bitchat/releases/tag/v1.8.0.

2026-11-14 00:43 MSK — Проверенный PR #1784 предлагал Wi-Fi LAN: общий локальный сегмент, обнаружение Bonjour и прямой TCP с Noise XX. Это не обязательно связь Wi-Fi Direct без точки доступа. На момент проверки PR закрыт и не объединён; в проверенном дереве main нет предложенного WIFI_TRANSPORT.md и реализации Wi-Fi-транспорта. Не считаем эту возможность готовой частью v1.8.0. Источник: https://github.com/permissionlesstech/bitchat/pull/1784.

2026-11-14 00:43 MSK — SECURITY.md обещает конфиденциальность и целостность частных сообщений через Noise на BLE и собственную схему приватных конвертов через Nostr. Публичные объявления и географические каналы публичны по устройству протокола; присутствие BLE наблюдаемо. Атаки истощения батареи также не исключены. Поэтому «полностью защищён» — неподтверждённое абсолютное утверждение. Источник: https://github.com/permissionlesstech/bitchat/blob/main/SECURITY.md.

## 2026-11-14 00:43 MSK — Следующий транспортный опыт

2026-11-14 00:43 MSK — Используем два согласившихся владельца NPU-устройств в одном локальном Wi-Fi-сегменте. NPU исполняют операции; сеть передаёт ограниченные конверты GG02. Проверяем совпадение выходов, порядок шагов, повтор без повторного исполнения, обрыв узла, подмену ревизии и состояние запроса. Задержку и расход батареи измеряем на этих устройствах, не выводим из рейтингов TOPS.

2026-11-14 00:43 MSK — Для первого модельного опыта каждый узел может держать весь Qwen3.5-0.8B и исполнять независимые запросы. Это репликация модельного сервиса, не разбиение одной генерации на NPU-слои. Для настоящего разделения нужны доступ к входам/выходам и состоянию слоёв, одинаковые веса/токенизатор/порядок вычислений и поддержанные ядра каждой платформы. Обычный чатовый интерфейс FLM не предоставляет такой договор сам по себе.

2026-11-14 00:43 MSK — Шифрование доставки не скрывает расшифрованные данные от вычисляющего узла и не доказывает правильность его работы. До публичного подключения незнакомых устройств нужны отдельные аутентификация, защита повторов, ограничения нагрузки и проверка результатов. Рабочий loopback-режим координатора ради этого опыта не переключается на публичное слушание.

2026-11-14 00:43 MSK — BLE не отвергается как класс транспорта, но передавать через него сотни мегабайт весов без измерения нецелесообразно. Предпочтительный проектный порядок: весовой пакет подготовить заранее; BLE использовать для малого управляющего обмена, локальную Wi-Fi-сеть — для основных данных. Этот выбор ещё должен пройти физическую проверку.
