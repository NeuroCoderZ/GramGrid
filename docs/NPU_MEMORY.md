Это архитектурная ёмкость, не измерение свободной SRAM процесса. Это не один общий буфер; отдельная память программ и регистры сюда не включены. Доказательство: docs/evidence/npu-memory-layout.json.

2026-11-13 21:38 MSK — Объяснение простыми словами: DDR — склад модели и состояний, SRAM внутри NPU — быстрый рабочий стол. Если небольшой вычислительный блок целиком помещается на стол, его веса можно удерживать там. Для тяжёлых шардов, длительных состояний и сетевых очередей системная память остаётся нужна. Хранение данных в DDR не означает, что математика выполняется на CPU.

2026-11-13 21:38 MSK — Документация XRT разделяет глобальную память (например DDR) и память AI Engine; обмен нужен, чтобы большие задачи не исчерпывали локальную память тайлов. Примеры управления xrt::graph для Versal не переносятся автоматически на Ryzen: текущий адаптер GramGrid использует собственный проверенный xrt::kernel.[3]

2026-11-13 21:38 MSK — В обычном матричном профиле GramGrid a/b/c являются HOST_ONLY буферами системной памяти, а Python pipeline имеет два обычных входа. Поэтому прежние weight_loads=[1,1] означали однократную подготовку весов в host BO и отсутствие повторной пересылки по сети, не вечное удержание весов в SRAM NPU. Весь стек приложения не становится независимым от DDR.

Доказательство: docs/evidence/npu-sram-batch4.json.

2026-11-13 21:38 MSK — Веса удерживаются внутри одного пакетного запуска. Удержание между независимыми запусками, сбросами и переключениями контекстов не заявляется. Физический трафик DDR аппаратными счётчиками не измерен. Нет обещания такой же экономии для полной LLM или по сети. Хостовые буферы, CPU-управление и сетевые пакеты всё ещё используют RAM; основная математика выполняется на NPU.

## 2026-11-13 21:38 MSK — Что неверно в пересланной таблице

2026-11-13 21:38 MSK — Нельзя принимать «вся SRAM доступна одному графу» или общие числа Qualcomm/Apple за паспорт каждого устройства. В официальном примере QNN отдельно указана адресуемая часть VTCM и резерв для других клиентов. Пример 8 MB физической / 7 MB адресуемой памяти не доказывает объём Realme пользователя.[4]

2026-11-13 21:38 MSK — Диапазоны 8–24 МБ для любого Hexagon, 16–32 МБ для любого ANE, одинаковые задержки 1–2 такта и скорость DDR 50–60 ГБ/с для нашего пути не подтверждены здесь. Они не используются в расчёте. HOST_ONLY не делает сетевой путь автоматически без копирования: текущий код содержит Vec, декодирование, копирование в BO и DMA. CRC в нашем кодеке программный и не является криптографической защитой.

## 2026-11-13 21:38 MSK — Следующее инженерное решение

2026-11-13 21:38 MSK — В сети учитываются два бюджета: системная память для назначенного шарда и состояний, а также выделяемая память NPU для рабочих тайлов и удерживаемых горячих данных. Объявлять архитектурные 6 МиБ свободными каждому узлу нельзя. Нужны память конкретного скомпилированного графа, резерв под буферы/стек и проверка выбранной платформы.

2026-11-13 21:38 MSK — Дальнейшая оптимизация: группировать поступающие задачи так, чтобы один весовой тайл обслуживал несколько вычислений, и перекрывать следующие загрузки с расчётом. Цена ожидания заполнения пакета измеряется отдельно. После этого нужен полный аппаратный блок выбранной архитектуры со scale/нормализациями/вниманием и состояниями, а не объявление matmul полноценной моделью.

2026-11-13 21:38 MSK — Человеческий шаг сейчас: найти одного добровольца с совместимым Ryzen AI для закрытого теста двух устройств, не покупать дополнительное железо только ради этого. Realme проверить после ремонта и появления его адаптера. Публичный запуск и выплаты пока не нужны. Исследовательский код можно показывать с честным описанием границ; письмо команде Telegram не является условием продолжения инженерной работы.
